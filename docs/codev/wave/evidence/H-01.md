## Checklist

- [x] **H-A1: Reproducible real-PyMOL invocation.** `tests/integration/test_real_pymol_command.py`
  registers `copilot` through real PyMOL's own `cmd.extend`/`cmd.do` against a
  real, running `pmc_server.transport.LoopbackPlanServer` driven by the real
  `pmc_server.lifecycle.PlanRequestLifecycle` — no transport/server/PyMOL
  doubles. `bazel test //tests/integration:real_pymol_command --lockfile_mode=error`
  → PASSED, 5/5 tests. Server start/stop wrapped in `try/finally`; PyMOL
  launched once per process (module-scoped fixture) and shut down with
  `cmd.do("quit")` at teardown.
- [x] **H-A2: Digest and correlation rejection.** `src/pmc_core/protocol.py`
  (`ValidatedPlanResponseV1.from_dict`) now raises `ProtocolDecodeError` when
  the action-plan and validation-report snapshot digests disagree.
  `tests/contract/test_protocol.py::test_validated_response_rejects_mismatched_snapshot_digests`
  and `::test_validated_response_accepts_matching_snapshot_digests_from_another_request`
  cover the changed-digest and matching-but-different-request cases; the HTTP
  client's separate request-relative digest/correlation checks in
  `src/pmc_client/transport.py` are unchanged and covered by
  `tests/integration/test_loopback_transport.py::test_client_rejects_response_for_a_different_snapshot`
  (updated so it genuinely exercises the transport-level check rather than
  the new codec-level one). `bazel test //tests/contract:protocol //tests/integration:loopback_transport --lockfile_mode=error` → PASSED.
- [x] **H-A3: Typed decode errors.** `src/pmc_core/protocol.py`
  (`_decode_command`) wraps `SelectOperation`/`ColorOperation` construction in
  `try/except ValueError as error: raise ProtocolDecodeError(...) from error`.
  `tests/contract/test_protocol.py::test_validated_response_rejects_unsupported_command_value_as_decode_error`
  and `::test_validated_response_rejects_unsupported_color_value_as_decode_error`
  assert `ProtocolDecodeError`, not a leaked `ValueError`. Valid V1 payloads
  still round-trip (`test_request_fixture_round_trips_as_strict_json`,
  `test_validated_response_round_trips_typed_action_plan`).
- [x] **H-A4: Bounded command failures.** `src/pmc_client/command.py`
  (`CopilotCommandClient.copilot`) catches `TransportError` around the
  transport submit call and reports `"copilot unavailable: {error}"` with no
  traceback, plan text, or mutation.
  `tests/integration/test_command.py::test_transport_failure_reports_bounded_diagnostic`
  covers the test-double path;
  `tests/integration/test_real_pymol_command.py::test_unavailable_server_path_reports_bounded_diagnostic`
  covers the real-PyMOL path (dead loopback port). No catch-all `except
  Exception` was added — only `TransportError` is caught.
- [x] **H-A5: Honest success output.** `_report_validated` in
  `src/pmc_client/command.py` now appends: *"copilot preview: this is a
  fixed, policy-checked plan preview. Loaded-state fidelity, execution, and
  scientific intent were not validated, and nothing was applied to this
  session. The snapshot value above is a fixture placeholder, not a computed
  structure checksum."* Asserted verbatim in
  `tests/integration/test_command.py`, `tests/integration/test_client_server_command.py`,
  and `tests/integration/test_real_pymol_command.py::test_success_path_previews_without_mutating_session`
  (real-PyMOL console transcript).
- [x] **H-A6: Real-session state remains unchanged.** `capture_session_state`/
  `assert_session_unchanged` in `test_real_pymol_command.py` compare object
  names, total atom count, `chain A`/`chain B` membership counts, per-atom
  coordinates (`cmd.iterate_state`), and per-atom colors (`cmd.iterate`)
  immediately before/after each invocation, for the success
  (`test_success_path_previews_without_mutating_session`), typed-rejection
  (`test_typed_rejection_path_reports_bounded_diagnostic`, using a real
  `PlanRequestLifecycle(policy_validator=always_deny)`), and
  unavailable-server (`test_unavailable_server_path_reports_bounded_diagnostic`)
  cases. All three assert zero difference. Declared comparison scope is
  exactly those fields; this does not claim whole-session or snapshot-fidelity
  recovery. The existing adapter-based regression
  (`tests/integration/test_client_server_command.py`) is retained separately.
- [x] **H-A7: Sabotage detects a mutation.** `test_sabotage_mutation_is_detected_by_state_comparison`
  deliberately recolors `chain A` between two snapshots and asserts both
  `before != after` and that `assert_session_unchanged` raises
  `AssertionError`. Only the disposable real-PyMOL test session (loaded from
  the local fixture, deleted after every test) is ever mutated.
- [x] **H-A8: Complete implementation evidence.** All codec/command changes,
  the real-PyMOL integration runner, and dependency/BUILD wiring are on
  branch `codev/H-01` / PR #11. Full validation (below) passed with no
  skipped required check on Linux/macOS. Limitations: (1) `cmd.get_coords("all")`
  cannot be used under this pinned wheel — its compiled extension was built
  against NumPy's pre-2.0 C API and raises `SystemError` under the resolved
  `numpy==2.5.2`; confirmed unfixable by pinning `numpy<2` (unsatisfiable
  against the wheel's own `numpy>=2.2` requirement) — `cmd.iterate_state` is
  used instead for the same observable (per-atom coordinates), disclosed in
  the test module's docstring; this may warrant a separate upstream report
  against `pymol-open-source-whl`. (2) Evidence covers one synthetic
  two-chain fixture, not a broader PyMOL-compatibility survey. (3) The
  real-PyMOL target is Windows-excluded (see Environment, above, and
  [issue #12](https://github.com/urban233/pymol-copilot/issues/12)) — H-A1/
  H-A6/H-A7 evidence is Linux/macOS only; every other target (codec/command
  hardening, existing test-double suites) is unaffected and runs on all
  three platforms. (4) A pre-existing, unrelated CI break on `main` since
  commit `7e57b55` (198 ruff style violations in `.claude/hooks/` and
  `.claude/skills/`, none of them product code) was also fixed in this PR
  by excluding `.claude/` from ruff's scope
  (`pyproject.toml`'s `extend-exclude`), since it blocked this PR's CI gate;
  this required adding an explicit `bazel_dep(name = "platforms", ...)` to
  `MODULE.bazel` so `target_compatible_with` could reference
  `@platforms//os:windows`. No apply, fetch, rollback, sidecar, or inference
  capability was introduced; the preview never executes the displayed plan.

## Observations

- Real-PyMOL console transcript (success path): `"copilot validation: passed"`,
  the canonical PML (`select copilot_selection, chain A\ncolor red, copilot_selection\n`),
  then the H-A5 disclaimer — asserted verbatim by
  `test_success_path_previews_without_mutating_session`.
- Pre/post state comparisons: object names, total atom count, `chain A`/
  `chain B` membership counts, per-atom `(index, x, y, z)` coordinates, and
  per-atom `(index, color_index)` pairs — zero difference across success,
  typed-rejection, and unavailable-server cases; declared scope does not
  include whole-session or on-disk state.
- Skipped tests and limitations: no test is silently skipped on the
  platforms where it runs. `//tests/integration:real_pymol_command` is
  explicitly `target_compatible_with`-excluded on Windows only (see
  Environment and H-A8 above, and issue #12); it runs and passes on Linux
  and macOS. The `cmd.get_coords`/NumPy-ABI limitation (see H-A8) is a
  substituted-API workaround, not a skipped check.
